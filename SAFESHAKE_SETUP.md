# SafeShake Setup Guide

This document covers setup and configuration for SafeShake, including Firebase, Google Sign-In, Android foreground service, SMS fallback, updates, and more.

---

## 1. Firebase Configuration

The `google-services.json` file must match your Firebase project and app package ID:

* `project_id`: `safeshake-ea0eb`
* `package_name` / `applicationId`: `com.wellsint.brainyte.safeshake`
* `mobilesdk_app_id`: `1:716607076837:android:a234f312c7223861add70c`

OAuth clients:

| client_type | client_id | Use |
|-------------|-----------|-----|
| 1 (Android) | `716607076837-c66op2kfd3lvpco40onc5g9llvvdfggg.apps.googleusercontent.com` | Android sign-in |
| 3 (Web) | `716607076837-kbr9fmomjdb61bpga5a8mnrboc0msc5a.apps.googleusercontent.com` | **Google Sign-In `serverClientId`** |

> **Important:** Always pass the **web client ID** (client_type 3) to Google Sign-In — never the Android client ID (client_type 1). Passing the Android client ID causes the "access token audience is not for this project" error.

### Dart config (`lib/firebase_options.dart`)

Generated by FlutterFire CLI. Contains `apiKey`, `appId`, `messagingSenderId`, `projectId`, `storageBucket`, and platform-specific client IDs for Android and iOS.

### iOS (`ios/Runner/GoogleService-Info.plist`)

Contains `API_KEY`, `GCM_SENDER_ID`, `PROJECT_ID`, `BUNDLE_ID`, `GOOGLE_APP_ID`, and `IS_SIGNIN_ENABLED`.

## 3. Force Update Dialog

SafeShake checks for a minimum required version at launch via Firestore:

* Collection: `app_config`
* Document: `version`
* Field: `min_version` (string, e.g. `"1.0.0"`)

If the installed app version is below `min_version`, a non-dismissible "Update Required" dialog appears and directs the user to the Google Play Store. To enable force updates, create/update the document:

```json
{
  "min_version": "1.0.0"
}
```

If the document is missing or unreadable, the app continues normally.

## 4. Android Permissions & Foreground Service

`android/app/src/main/AndroidManifest.xml` declares:

* `INTERNET`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`
* `POST_NOTIFICATIONS`, `SEND_SMS`, `VIBRATE`
* `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `FOREGROUND_SERVICE_SPECIAL_USE`
* `RECEIVE_BOOT_COMPLETED`

The native `SafeShakeForegroundService` runs as a foreground service with a visible notification so the system does not terminate the shake listener.

A `BootReceiver` restarts protection on device boot if it was active.

---

## 5. SMS Fallback Setup

SafeShake falls back to cellular SMS when there is no internet connection. Required on Android:

1. `SEND_SMS` permission (declared in `AndroidManifest.xml`).
2. Contact phone numbers are saved locally in `SharedPreferences` under the key `sms_numbers` whenever contacts are added, updated, or deleted.
3. `SmsManager.sendTextMessage` sends the emergency message to all enabled contact numbers.

No server-side configuration is needed for SMS — it uses the device's cellular connection.

---

## 6. Battery Optimization (Android)

During onboarding, users are guided through a **Battery Optimization** step:

> On Android: Settings → Apps → SafeShake → Battery → Unrestricted

This prevents the OS from putting the background monitoring service to sleep. Without this, Android may kill the foreground service and stop shake detection.

---

## 7. Location in Emergency Alerts

SafeShake fetches the user's exact latitude and longitude:

* **Android:** `FusedLocationProviderClient` via `com.google.android.gms.location`
* **iOS:** `CoreLocation` via `geolocator`

Coordinates are formatted as a Google Maps URL:

```
https://maps.google.com/?q=<latitude>,<longitude>
```

The last known location is cached in `SharedPreferences` (24-hour max age) and used immediately if a fresh GPS fix times out during an emergency.

---

## 8. Shake Detection (False-Alarm Prevention)

SafeShake requires **two shakes within 3,000 ms** before triggering an alert. A cooldown period prevents repeated rapid alerts. Sensitivity thresholds (Low / Medium / High) are configurable in Settings.

---

## 9. Emergency Contacts

* Maximum 5 contacts.
* Each contact must have a unique phone number (duplicates are rejected, normalized by removing spaces, dashes, and parentheses).
* Users receive a notification when a contact is added or removed.
* At least one enabled contact with a valid email address is required for email alerts; phone numbers are used for SMS fallback.

---

## 10. Manual SOS

A large "MANUAL SOS" button is always available on the Home screen for situations where a shake gesture is not possible.

---

## 11. WhatsApp Auto-Share (Feasibility)

**Not feasible as a fully automatic background action.** WhatsApp does not allow apps to send messages programmatically without explicit user interaction. Possible alternatives:

* Open `https://wa.me/?text=<message>` or `whatsapp://send?text=<message>` via `url_launcher` to pre-fill a message, but the user must tap "Send".
* This cannot run from a background/foreground service context without user interaction.
* **Recommendation:** If desired, add a manual "Share via WhatsApp" button in the UI that opens WhatsApp with the pre-filled emergency message for the user to send.

## 14. Troubleshooting

| Issue | Likely Cause | Fix |
|-------|-------------|-----|
| Google Sign-In "audience not for this project" | Android client ID passed instead of web client ID | Pass `client_type: 3` web client ID as `serverClientId` |
| Protection toggle stops working | Battery optimization killed the service | Set SafeShake to "Unrestricted" in Android battery settings |
| No location in alert | Location permission denied or service disabled | Grant location permission and enable location services |
| Alert fails with no internet | No network connectivity | SMS fallback triggers automatically if contact numbers are saved |
| Duplicate contact rejected | Phone number already exists (normalized) | Use a unique phone number for each contact |
| Force update dialog appears | App version below `min_version` in Firestore | Update the app or adjust `app_config/version.min_version` |
